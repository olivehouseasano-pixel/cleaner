## 設置方法(既存サイトへの追加)

**重要:私(Claude)はレンタルサーバーへのFTP/SFTP・管理画面へのログイン手段を持っていません。**
既存サイト(https://yanekouji-wagaraku.com/)へのファイル設置は、お客様またはサーバー管理者様の作業となります。以下はそのための手順です。

1. **既存サイトのバックアップを取ってください**(サーバー全体、または最低限ドキュメントルート配下)。多くのレンタルサーバーには管理画面にバックアップ機能があります。
2. サーバーの `public_html`(または同等のドキュメントルート)直下に **新しく `cleaner` という名前のフォルダを作成**してください。
   既存ページのURLやファイルには一切触れません(例:`https://yanekouji-wagaraku.com/` のトップページや他のディレクトリはそのままです)。
3. `cleaner` フォルダの中に、この一式(`index.html` / `send_order.php` / `images/` フォルダ)をそのままアップロードしてください。
   アップロード後の構成は次のようになります。
   ```
   public_html/
   ├─ (既存サイトのファイル群 … 触れません)
   └─ cleaner/
      ├─ index.html
      ├─ send_order.php
      └─ images/
         ├─ ikkiga-package.jpg
         ├─ ... (計10枚)
   ```
4. アップロード後、`https://yanekouji-wagaraku.com/cleaner/` にアクセスして表示を確認してください。
   - 現在 `index.html` には `<meta name="robots" content="noindex,nofollow">` を設定済みです。本番公開の最終確認が終わるまでは、この設定をそのまま維持してください(下記「本番公開直前に行うこと」参照)。
5. 動作確認(下記「完成後のチェック」参照)が終わったら、必要に応じて既存サイトのメニュー・トップページ等から `/cleaner/` へのリンクを追加してください(この作業も既存ファイルの編集になるため、事前バックアップの上、変更箇所を最小限にしてください)。

ページ内のURL(canonical・OGP・構造化データ)は、公開URLが `https://yanekouji-wagaraku.com/cleaner/` になる前提であらかじめ設定済みです。もし実際の設置パスが `/cleaner/` 以外になる場合は、`index.html` 内の当該箇所の差し替えが必要です。

### サーバー環境について(要確認)
既存サイトの技術構成(WordPressか、静的HTMLか、他のCMSか等)を確認できていません。特に以下の点はお客様側でご確認をお願いします。
- サーバーがPHPに対応しているか(`send_order.php` の動作に必要です)
- `.htaccess` 等でURL構造を制御している場合、`/cleaner/` 配下が意図せずブロック・リダイレクトされないか
- 既存サイトが WordPress 等のCMSの場合、`cleaner` フォルダがCMSのルーティングと衝突しないか(基本的には独立フォルダなので問題ない想定ですが、念のため確認をお願いします)

- `index.html` の `<meta name="robots" content="noindex,nofollow">` を削除(または `index,follow` 等に変更)してください。
  - **現在は制作会社によるテスト設置段階のため、意図的に検索エンジンから隠しています。**

  - 解除を忘れると本番公開してもGoogle等に表示されません。逆に確認が終わる前に解除すると、未完成のページが検索結果に出てしまう可能性があります。

## セキュリティ対策(実装済み)

- **CSRF対策**:Double Submit Cookie方式。ページ読込時にランダムトークンを生成しCookieと送信データの両方に含め、`send_order.php` で `hash_equals` により一致検証しています。
- **honeypot**:通常利用者には見えない `hp_website` という隠しフィールドを注文フォームに設置しています。ここに値が入って送信された場合はBOTとみなし、**成功したように見せかけつつ実際にはメールを送信しません**(ボットに検知されたことを悟らせないための意図的な挙動です)。
- **送信前最低3秒**:ページ表示時刻をCookie(`page_loaded_at`)に記録し、送信時刻との差が3秒未満の場合はBOT疑いとして拒否します(HTTP 429)。
- **セッションレート制限(既存)**:同一セッションから10秒以内の連続送信を拒否します(二重送信対策、上記の3秒チェックとは別に維持)。
- **商品ホワイトリスト**:`send_order.php` 内に正式な商品・セット名と価格の対応表を保持し、送信された商品名がこの一覧に完全一致しない場合はその項目を除外します。送信された商品がすべて一覧外だった場合はリクエスト自体を拒否します。価格はこの一覧の値のみを使用し、ブラウザから送られてきた表記は一切信用しません。
- **数量制限(1〜20)**:カートの数量はブラウザ側UIで1〜20の範囲に制限しているほか、`send_order.php` 側でも同じ範囲にクランプ(範囲外の値は1または20に補正)しています。
- **PHPエラー非表示**:`display_errors` / `display_startup_errors` を無効化し、想定外のエラーは `try/catch` で捕捉して利用者には一般的なエラーメッセージのみを返します(内部のパスやエラー内容は返しません)。エラー自体はサーバーの標準エラーログには記録されます。
- **DOM生成の安全化**:カート一覧の描画は `innerHTML` への文字列連結をやめ、`createElement` / `textContent` を使う実装に変更しています。
- **個人情報の非保存**:今回の実装でもDB・ファイルへの新規保存は追加していません。注文情報はメール送信のみで、ブラウザにも保存しません(localStorage等は未使用)。
